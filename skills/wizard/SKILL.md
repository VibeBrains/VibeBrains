# wizard

Мастер — bash-скрипт, который ведёт человека шаг за шагом по ручной процедуре: открывает нужный адрес, говорит, что нажать и что скопировать, принимает значение, кладёт его куда следует (`.env`, секреты репозитория), подтверждает каждый этап и показывает, сколько осталось.

## Зачем

Есть шаги, которые агент сделать не может и не должен: войти в чужую панель, выпустить ключ, ввести пароль. Объяснять их словами каждый раз заново — долго, а человек всё равно теряется на третьем экране. Мастер превращает объяснение в процедуру, которую нельзя пройти не по порядку.

Удобство уже решено в [template.sh](template.sh): прогресс по этапам, подтверждения, открытие адресов на разных системах, скрытый ввод секретов, повторяемая запись в `.env`, запись секретов и переменных через `gh`, итоговая сводка. **Работа агента — очертить процедуру и написать её этапы.** Библиотека выше метки `STAGES` одинакова в каждом мастере — её не правят руками.

Мастер по умолчанию одноразовый: собран под один прогон, лежит во временном каталоге или в `scripts/`, удаляется по завершении. В репозиторий его кладут, только если нужен повторяемый путь настройки.

## Порядок

### 1. Очертить процедуру

Выяснить каждый ручной шаг и каждое значение, которое по дороге появляется. Сначала читать репозиторий, а не спрашивать с порога:

- для настройки — `.env`, `.env.example`, `README`, файлы compose, конфигурацию фреймворка и конвейеры CI: каждое обращение к секрету или переменной там — значение, которое мастер должен добыть;
- для миграции — текущее состояние, целевое и необратимые действия между ними.

Показать человеку упорядоченный список этапов и значений и подтвердить его.

**Готово, когда** этапы названы по порядку и про каждое значение известно: где человек его берёт, куда оно пишется (`.env`, секрет, оба или никуда — этап может быть чистым действием) и секретное ли оно.

### 2. Расписать путь каждого этапа

Точный маршрут: какой адрес открыть, что там сделать, где показано значение, какую переменную оно заполняет. Где нынешний интерфейс или точная команда неизвестны — сказать об этом и спросить или свериться с документацией. **Шаги, которых может не существовать, не выдумывают.**

**Готово, когда** по каждому этапу есть указания, которым последует посторонний.

### 3. Написать мастер

Скопировать `template.sh` по нужному пути. Пример заменить своими этапами в порядке зависимости, через помощников библиотеки: `stage`, `say`/`step`, `open_url`, `ask`/`ask_secret`, `write_env`, `set_secret`/`set_var`, `pause`/`confirm`. В `TOTAL_STAGES` — число этапов.

Тексты этапов — на языке человека, который будет их читать.

Планка шаблона: адрес открывается до вопроса о значении; всё секретное — через `ask_secret`; каждое сохраняемое значение — через `write_env`; `set_secret` — только для того, что действительно нужно CI; перед необратимым — `confirm`. Каждый `stage` очищает экран: один этап — одна задача.

### 4. Проверить и отдать

- `bash -n <скрипт>`; `shellcheck`, если есть.
- `chmod +x <скрипт>`.
- **Целиком не запускать:** мастер открывает браузер и ждёт человека. Проследить статически: каждое значение из шага 1 принято и ложится туда, куда сказано, имя каждого `set_secret` совпадает с обращением в CI.
- Сказать человеку, как запустить.

## Что запрещено

- **Вводить секреты за человека.** Мастер существует ровно для того, чтобы их вводил он.
- **Править библиотеку выше метки `STAGES`.**
- **Собирать мастер для шагов, которые агент может выполнить сам.**
