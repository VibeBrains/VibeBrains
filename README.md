# .vibe — окружение проекта (VibeIDE / VibeIDEA)

Эта папка — конфигурация агентской обвязки для ЭТОГО проекта; формат один на оба
продукта VibeBrains (VibeIDE и VibeIDEA).
Создана автоматически; всё в ней опционально. Файлы `*.example.jsonc` — образцы:
скопируйте нужный в файл без `.example` (строгий JSON, без комментариев) — и он заработает.

| Файл | Что включает |
|---|---|
| `hooks.json` | Команды проекта вокруг действий агента (запрет/линт/тесты). Включается в Settings → Tools → VibeIDEA → Агент |
| `pipelines.json` | Цепочки шагов-ролей (планировщик → разработчик → ревьюер) |
| `servers.json` | Дев-стек: волны запуска, readyCheck, зависимости |
| `providers/` | Каталог LLM-провайдеров для прямого чата — читается автоматически, тумблер `active`; `providers.json` (опционально) накладывается поверх |
| `modelQuirks.json` | Что конкретная модель отказывается принимать в запросе (VibeIDEA) |
| `rules.md` | Правила проекта для агента (подтягиваются через `@agent`) |
| `design/` | Дизайн-контекст: uiKit.md и components.md подмешиваются агенту при работе с UI |

Рядом появляются рабочие журналы (`checkpoints.jsonl`, `audit.jsonl`) — они
в `.gitignore` этой папки и в git не попадают.

Полные спеки форматов (можно скормить любой LLM): docs/vibe/manuals/*Spec.md
в репозитории VibeIDEA, либо попросите агента в чате: «создай мне .vibe/hooks.json».

## Источник этой папки

Канонический образ `.vibe` живёт в репозитории **VibeBrains** и подключён в оба продукта
git-submodule-ом (VibeIDEA: `vibe-plugins/vibe-agent/resources/vibeDefaults`; VibeIDE:
`.vibe-defaults`) — правки набора делаются в VibeBrains и одним `git submodule update
--remote` доезжают до второго продукта. В проекты содержимое засевается create-if-missing: ваши правки здесь никто не перетирает.

**Ревизии и обновление.** `versions.json` (служебный, не засевается) хранит для каждого файла
набора номер ревизии, sha256 текущей версии и `history` — sha всех прошлых. По ним продукт
отличает нетронутую копию старого релиза (обновляется молча — терять нечего) от вашей правки
(не трогаем никогда; если ревизия в наборе ушла вперёд — покажем уведомление со сравнением).
Правите набор — прогоните `node bump.mjs` ДО коммита: он поднимет ревизии изменившимся файлам
и сложит прошлые sha в историю. `node bump.mjs --check` — тот же гейт, что прогоняют оба
продукта на тестах. Файл, удалённый или переименованный в наборе, переезжает в `deprecated.json`
(тоже служебный) со своей историей — сеялки удаляют из проектов только НЕ правленные копии.
