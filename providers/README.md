# Каталог провайдеров — `.vibe/providers/`

Готовые конфиги LLM-провайдеров, по файлу на провайдера — **единый набор для обоих
продуктов**, и роль у него одна: **рабочий реестр**, который читается автоматически.
Копировать записи никуда не нужно — они работают как есть, тумблер `active`.

Каталог играет роль «встроенных провайдеров» и лежит в **слабейшем слое**: ваш
`providers.json` (и проектный, и глобальный `~/.vibe/`) всегда сильнее засеянного файла
с тем же `id`. Порядок слоёв, от слабого к сильному:

```
~/.vibe/providers/*.jsonc  →  <проект>/.vibe/providers/*.jsonc  →  ~/.vibe/providers.json  →  <проект>/.vibe/providers.json
```

Внутри одной папки файлы читаются по алфавиту, поэтому поздний по имени перекрывает раннего
(поле за полем; `models.static` — по id модели).

**Тумблер — `active`.** Все провайдеры каталога включены; заработает тот, у кого появится
ключ. Не нужен — поставьте `"active": false` в его файле, и он исчезнет из списков (в слиянии
и `extends` продолжит участвовать). Можно и не трогая каталог — переопределением в своём
`providers.json`: `{ "id": "openai", "active": false }`; так решение переживёт обновление
набора. Запись без поля `active` считается активной.

Три осознанных исключения: `_template-openai-compatible.jsonc` — образец для копирования
с вымышленным endpoint, `meta-muse-contributor` — тариф, отдающий ваши промпты и код
вендору на обучение, и `arbr` — свой шлюз, у которого адрес по умолчанию указывает на
вашу же машину: включать его есть смысл только тому, кто этот шлюз поднял.

**Порядок наложения** (последний сильнее): каталог `~/.vibe/providers/` → каталог
`<проект>/.vibe/providers/` (внутри каталога — файлы по алфавиту) →
`~/.vibe/providers.json` → `<проект>/.vibe/providers.json`.

**Ключи API в файлах не живут никогда** — только `apiKeyEnv` (строка `ИМЯ=ключ` в
`.vibe/.env` или переменная окружения ОС) либо `apiKeyRef` (защищённое хранилище ОС; поле
ввода — Settings → Tools → VibeIDEA → Провайдеры). Сначала включите провайдера, потом
вводите ключ: карточка в настройках появляется только у активных.

**Модели не вшиты** — список подтягивается с каталога провайдера (`models.fetch`) после
подключения ключа. Нужна модель, которой нет в каталоге, или фиксированные параметры
(temperature, `extraBody`, `vision: false`, FIM) — объявите **кастомную модель** в
`models.static`: она получит бейдж «кастом» в списке (если перестала отвечать — возможно,
у провайдера её больше нет). Рецепт — `_template-openai-compatible.jsonc`, полная спека —
`docs/vibe/manuals/providersSpec.md`.

Ключ, применённый в настройках, панель подхватывает сразу; правки самих файлов видны
при переоткрытии панели/страниц настроек или перезапуске IDE; значение ключа в
`.vibe/.env` подхватывается без рестарта.

## Свой `providers.json`: патч, клон и провайдер с нуля

Каталог отвечает на вопрос «какие провайдеры есть», а `providers.json` — на вопрос «что я хочу
изменить». Он сильнее каталога, поэтому туда пишут **только отличия**, и решение переживает
обновление набора: засеянный файл может смениться, ваш — нет.

Раньше эти рецепты жили отдельным файлом `providers.example.jsonc` — двойником рядом с рабочим
`providers.json`. Двойник убран: примеры конфигов теперь либо сразу рабочие файлы с выключенными
записями, либо, как здесь, документация рядом с тем, что документируют.

**Идентификаторы для патча берутся из имён файлов каталога** (`anthropic`, `openai`, `zai`,
`minimax`, `qwen`, `deepseek`, `kimi`, `ollama`, `openrouter`, …) — то есть из того, что лежит
рядом. Собственного списка «встроенных» у VibeIDEA нет: встроенное и есть каталог.

```jsonc
{
  "version": 1,
  "providers": [
    // 1. Свой OpenAI-совместимый провайдер с нуля.
    {
      "id": "my-proxy",
      "name": "Мой прокси",
      "order": 10,                 // порядок среди ВАШИХ (меньше = выше)
      "protocol": "openai",        // openai | anthropic | gemini
      "baseURL": "https://llm.mycorp.local/v1",
      "auth": { "type": "header", "name": "x-api-key" },  // или "bearer"
      "apiKeyEnv": "MYCORP_LLM_KEY",
      "headers": { "x-team": "platform" },
      "timeoutMs": 120000,
      "models": { "fetch": true }
    },

    // 2. Патч каталожного провайдера: совпал id — поля накладываются поверх.
    { "id": "openai", "active": false },                       // выключить целиком
    { "id": "minimax", "models": { "static": [                 // выключить ОДНУ модель
      { "id": "MiniMax-M2", "active": false }
    ] } },

    // 3. Клон через extends: оригинал остаётся на месте.
    {
      "id": "openrouter-fav",
      "extends": "openrouter",
      "name": "OpenRouter — избранное",
      "order": 20,
      "models": { "fetch": false, "static": [ { "id": "x-ai/grok-4", "default": true } ] }
    },

    // 4. «Думающая» модель: объявленные уровни + вендорский тумблер в extraBody.
    {
      "id": "kimi",
      "models": { "fetch": false, "static": [
        {
          "id": "kimi-k2.7-code",
          "contextWindow": 262144,
          "maxOutputTokens": 32768,
          "reasoning": { "canTurnOff": true, "effort": ["low", "medium", "high"] },
          "extraBody": { "thinking": { "type": "enabled" } }
        }
      ] }
    }
  ]
}
```

Три правила, о которые спотыкаются чаще всего:

- **Ключи в этот файл не пишут.** Источник — `apiKeyEnv` (`.vibe/.env` или окружение машины) либо
  `apiKeyRef` (защищённое хранилище IDE). Сам `providers.json` можно коммитить.
- **Сравнение id не различает регистр и дефисы:** `openrouter`, `openRouter` и `open-router` —
  один и тот же провайдер.
- **Смена структуры (id, baseURL, список моделей) требует перезапуска**, а вот значение ключа в
  `.vibe/.env` подхватывается на лету.
